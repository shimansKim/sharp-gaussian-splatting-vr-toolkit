# Quest 앱 조작표

어떤 버튼이 어떤 동작인지는 **배정 표**가 정한다: 기본값은 `quest-app/src/core/bindings.js`의 `ACTIONS`, 사람이 바꾼 값은 기기(localStorage `sharp.input.bindings.v1`)에 저장된다.
모든 뷰어는 이 표대로 입력을 판정한다(`core/input-map.js`). 아래 표들은 **기본값** 기준이고, 바꾼 배정은 VR 공용 패널 안내 줄·PLY 안내 카드·설정창에 그대로 보인다.
기본값을 바꿀 때는 `bindings.js`의 `ACTIONS`를 고치고 아래 "버튼 지정" 표를 맞춘다(테스트 `tests/bindings.test.js`가 둘이 같은지 본다).

## 버튼 지정(사람이 바꾸기)

- **앱**: 2D 화면 [설정] > [컨트롤러 버튼 지정]. 동작마다 드롭다운으로 손·버튼(트리거·그립·X/A·B/Y·스틱 누르기)·짧게/길게, 또는 스틱·축(좌우·상하)을 고른다. 바꾸면 바로 저장되고 적용된다. [기본]은 그 줄만, [모두 기본값으로]는 전부 되돌린다.
- **VR 안**: 공용 패널 [더 보기] > [컨트롤러 버튼 지정]. 범위 탭(모든 화면·영상/사진·PLY)에서 동작 줄을 트리거로 누르면 "지정할 버튼을 누르세요" 상태가 되고, 누른 버튼(떼면 '짧게', 0.8초 넘게 누르면 '길게')이나 끝까지 민 스틱 방향(좌우·상하)이 그 동작에 지정된다. 트리거로 지정하려면 레이가 패널 밖을 가리킬 때 당긴다(패널을 가리키면 패널 버튼 누르기). [양손]을 켜면 B/Y처럼 어느 손이든 같은 버튼으로 지정된다. [취소]·[이 줄 기본값]·[지정 안 함]·[모두 기본값]이 있다. 지정하는 동안과 손을 다 뗄 때까지는 그 입력이 UI 켜기·끄기나 이전·다음을 실행하지 않는다.
  - 안전장치: UI 켜기·끄기(메뉴로 돌아오는 길)는 비워 둘 수 없고 트리거에 둘 수 없다(2D·PC 설정창도 같다). VR에서 UI 켜기·끄기를 바꾸면 10초 안에 새 버튼을 한 번 눌러 확인해야 하고, 확인하지 않으면 원래 버튼으로 되돌린다.
- **PC**: PC 서버를 켜고 PC 브라우저에서 `http://localhost:8787/settings/bindings`(또는 서버 창에 나온 PC 주소 + `/settings/bindings`)를 연다. 같은 목록·같은 충돌 검사로 고르고 [PC에 저장]을 누른다.
- **둘 다 바꿨을 때**: **나중에 바꾼 쪽이 이긴다.** 앱이 PC에 연결되면 PC 배정의 바꾼 시각과 이 기기 배정의 바꾼 시각을 비교해, PC가 더 최근이면 받아 오고 기기가 더 최근이면 PC로 보낸다. 설정창 맨 위에 지금 배정의 출처(기본값·이 기기에서 바꿈·PC에서 받아 옴)와 시각이 보이고, PC 연결 중에는 [PC 배정 불러오기]·[이 배정을 PC로 보내기]로 직접 고를 수도 있다.
  - 이 기기에서 바꾼 배정이 PC의 더 최근 배정에 밀려 버려지면 2D 상태줄·VR 공용 패널 안내 줄·영상/사진 재생 컨트롤 안내에 알리고, 설정창에 경고 줄이 남는다(다시 바꾸면 사라진다).
  - 시각은 기기 시계를 쓴다. PC 서버는 받은 시각을 '지금 + 5분'까지만 인정한다(시계가 앞선 기기가 다른 쪽 변경을 오래 막지 못하게).
  - PC에 저장(PUT)할 수 있는 곳은 앱이 호스팅되는 출처, 서버의 `--allow-origin`, PC 설정 페이지(같은 출처)뿐이다. 읽기는 예전과 같다.
- **충돌**: 같은 범위(모든 화면·영상/사진·PLY)에서 같은 입력에 동작이 둘 걸리면 설정창(앱·PC)에 경고가 뜬다. 저장은 막지 않으며 둘 다 동작한다. 같은 버튼의 '짧게'와 '길게'는 따로 쓸 수 있고(B/Y 기본값이 그렇다), 같은 스틱의 좌우·상하에 서로 다른 동작을 두면 대각선으로 밀 때 더 크게 민 축 하나만 쓴다. 영상·사진과 PLY는 범위가 달라 같은 입력을 써도 된다.
- 같은 버튼에 '길게' 동작이 함께 있으면 '짧게' 동작은 버튼을 뗄 때 일어나고, 없으면 누르는 순간 일어난다.

### 기본 배정 바뀜(판 2, 2026-11-13 사람 요청)

- **A = 파일 선택 화면 열기·닫기**("파일 선택 화면으로 돌아가는 버튼"). 목록이 보이는 중이면 닫고, 아니면 연다(UI를 꺼 두었으면 켠다). 목록이 보이는 동안 PLY·영상·사진 출력은 멈춘다(#59).
- **다음 파일 = X 길게**(이전 = X 짧게). A를 파일 선택에 내주면서 이전·다음을 X 한 버튼에 모았다. 근거: 자주 넘기는 영상·사진은 오른쪽 스틱 좌우(튕기기·10초)로 넘기므로 X 길게는 PLY·보조용이고, 한 버튼 짧게/길게는 이미 B/Y(UI 켜기·끄기/옮기기)에서 쓰는 규칙이다. B/Y는 UI 길(메뉴로 돌아오는 길)이라 건드리지 않았다. X 짧게(이전)는 X 길게가 함께 있어 버튼을 뗄 때 넘어간다.
- **오른쪽 트리거(레이가 패널 밖일 때) = 영상·사진 재생 컨트롤 표시·숨김.** 레이로 패널 버튼을 누르는 '선택'은 그대로다.
- **재생·일시정지는 기본 버튼이 없다**: 재생 컨트롤의 ▶/❚❚ 버튼으로만 한다. 원하면 설정창에서 따로 지정할 수 있다.
- 예전(판 1)에 사람이 바꾼 배정은 그대로 둔다. 기본값만 바뀌며, 새 기본값(A = 파일 선택, X 길게 = 다음, 트리거 = 재생 컨트롤)이 사람이 직접 고른 입력과 겹치면 그 새 동작은 '지정 안 함'으로 둔다(사람의 선택을 빼앗지 않음, `migrateOverrides`).

## UI 위치 고정과 켜기·끄기

UI는 **저절로 따라오거나 옮겨지지 않는다.** 폴더·파일을 고르는 **목록 창은 눈높이 정면**에 열리고, 영상·사진 **재생 컨트롤·PLY 안내는 정면 아래쪽**(머리 쪽으로 기울인 한 자리)에 고정되어 시야 한가운데를 가리지 않는다.

- 재생 컨트롤·PLY 안내의 자리(UI 앵커)는 VR을 시작하고 헤드셋 자세가 들어온 직후 한 번 정해진다(그때의 머리 위치·정면 기준). 그 뒤 머리를 돌리거나 걸어도, 패널을 열고 닫거나 파일·형식을 바꿔도 **자리는 그대로**다. PLY에서 스틱으로 걸어 다니면 UI도 같이 따라가지만(방에 고정), 머리 움직임은 따라가지 않는다.
- **켜고 끄기**: B/Y를 짧게 누르면 모든 UI가 한꺼번에 꺼지고, 다시 누르면 같은 자리에 같은 상태로 돌아온다. UI가 켜져 있는데 보이는 것이 하나도 없으면(빈 화면) B/Y가 공용 패널을 연다.
- **목록 창**: 사람이 열 때(B/Y로 열기·재생 컨트롤의 [목록])의 시선 정면, 눈높이, 1.25m 앞에 열리고 열려 있는 동안 고정된다. 다시 열면 그때의 정면에 열린다. B/Y로 껐다 켜면 같은 자리로 돌아온다.
- **파일을 고르면**: 목록 창이 자동으로 숨고, 고른 영상·사진이 그 순간의 정면에 놓이며(L3 위치 맞춤과 같은 동작), 재생 컨트롤이 그 화면 아래쪽에 나온다(UI 앵커도 그 순간의 정면으로 옮겨진다). PLY는 기존 맞춤 동작 그대로 열리고 안내가 아래쪽에 뜬다. A/X·스틱으로 파일을 **넘길 때**는 화면·UI 자리가 그대로다(목록에서 직접 고를 때만 정면에 놓는다). 고르는 동안 B/Y로 UI를 껐으면 아무것도 옮기지 않고 목록만 닫는다.
- **옮기기(사람이 직접 할 때만)**: B/Y를 0.8초 이상 누르고 있거나, 패널의 [여기로 옮기기] 버튼을 누르면 UI가 지금 보는 방향 아래쪽으로 옮겨진다. 패널·재생 컨트롤·PLY 안내가 함께 옮겨진다.
- 그립·스틱·A/X는 UI 조작에 쓰지 않는다.

개발자용: 상태는 `quest-app/src/core/ui-state.js`(`ui.visible`, `ui.reference(camera)`, `ui.relocate(camera)`, 이벤트 `ui:visibility`·`ui:anchor`)이고, B/Y 처리는 `src/ui/ui-controls.js`다. 새 UI를 만들면 `ui.visible`이 꺼져 있을 때 띄우지 말고, 자리는 `ui.reference(camera)`로 얻는다.

## 영상·사진 줌과 화면 자리

- 화면 자리는 세션을 시작하고 처음 파일을 열 때 한 번 정해지고, 파일을 넘기거나 형식·눈 바꿈을 바꾸거나 머리를 돌려도 **저절로 옮겨지지 않는다**. 스틱으로 돌려 둔 방향도 파일을 넘겨도 이어진다. 자리를 바꾸는 것은 L3와 재생 컨트롤 [더 보기]의 [화면 위치 맞춤](지금 보는 방향 앞으로, 돌려 둔 양도 지움)뿐이다.
- 줌: 오른쪽 스틱 상하(위로 밀면 확대)나 재생 컨트롤의 [줌 −] [줌 +]. 공용 패널이 열려 있으면 스틱 상하는 목록 넘기기이므로 줌하지 않는다.
  - 가상 스크린(평면 3D·2D): 스크린 크기(시야각) 배율 0.15~3배. 처음 크기는 가로 약 62°(예전 약 90°보다 작게).
  - 360/180: 시야각 확대 1~4배(원래보다 작게는 못 줄인다). 확대하는 동안에는 컴포지터 레이어로는 못 보여 줘 메시 경로로 그린다.
- 줌 값은 기기(localStorage, 키 sharp.media.zoom.v1)에 기억해 파일을 넘기거나 앱을 다시 켜도 유지한다. 스크린 배율과 구 확대는 따로 기억한다.

## Quest 기본 앱의 관례와 비교한 근거

- 트리거=선택: Meta 시스템 UI·브라우저·Skybox·Quest TV가 모두 같다.
- 그립=잡기, 양손 그립=크기: Horizon·3D 보기 앱의 관례.
- 오른쪽 스틱 좌우=스냅 회전: Meta 이동 표준. 영상 플레이어(Skybox·Quest TV)는 좌우가 되감기·빨리감기, 갤러리는 좌우 튕기기가 이전·다음 사진이다. 이 앱의 영상·사진은 사람 요청(실기기 2026-11-12)으로 두 스틱을 맞바꿔, 왼쪽 스틱을 화면 회전(L3 = 위치 맞춤)에, 오른쪽 스틱을 좌우 되감기·이전/다음과 상하 줌에 쓴다. PLY는 그대로다.
- B/Y=뒤로·메뉴, A/X=확인·다음 단계: 앱마다 다르지만 B/Y가 취소·메뉴인 점은 공통이다.

## VR 파일 선택창 (왼쪽 폴더 트리 / 오른쪽 파일 목록)

- **선택창만 보임**: VR에서 파일 선택창(목록 화면)이 보이는 동안 PLY·영상·사진은 출력을 멈추고 숨긴다(영상 일시정지, 미디어 레이어·화면·재생 컨트롤 숨김, PLY는 메시와 SparkRenderer를 장면에서 빼서 정렬·갱신·그리기·입력 처리·자동 화질 측정을 모두 멈춤. 메모리에는 남겨 두어 닫으면 바로 다시 붙는다). 배경은 어두운 빈 공간이다.
  - 파일을 고르면 선택창이 닫히고 그 파일이 정면에 나온다(영상은 처음부터 자동 재생).
  - 고르지 않고 닫으면(B/Y·✕·[재생 컨트롤 보기]) 이전 파일이 같은 자리에 돌아온다. 영상은 멈춘 위치 그대로이고, 열기 전에 재생 중이었으면 이어서 재생, 일시정지였으면 그대로 둔다.
  - [더 보기]·PLY 옵션 화면에서는 장면이 보인다(설정을 바꾸며 결과를 보도록).
  - 2D 화면은 목록과 미리보기가 나란히 있는 구조라 그대로 둔다(겹쳐 그리지 않음).
- **왼쪽 폴더 트리**: 출처(이번에 연 파일·보관함·PC·드라이브) 아래에 폴더가 달린다(폴더를 지원하는 PC만 펼칠 수 있음). 이름을 누르면 그 출처·폴더의 목록이 열리고(현재 폴더는 초록색), [▸]/[▾]는 펼치기·접기다. 하위 폴더는 필요할 때만 불러온다: 폴더를 열면 그 목록이 준 하위 폴더를 그대로 쓰고, [▸]로 펼칠 때만 그 폴더의 하위 폴더를 따로 받는다. 트리는 [▲ 폴더] [▼ 폴더]로 넘긴다.
- **오른쪽 파일 목록**: 위에 [종류] [정렬]과 넘기기 줄(⏮ −100 ▲ ▼ +100 ⏭), 그 아래에 선택한 폴더의 파일(프레임 시퀀스 묶음 포함). 제목 줄에 지금 보는 출처·폴더가 나온다. 파일을 고르면 목록이 숨고 그 화면이 열린다(위 "파일을 고르면").
- **스틱**: 목록 창이 열려 있으면 스틱 상하는 레이가 가리키는 칸을 넘긴다(왼쪽 트리 위를 가리키면 트리, 그 밖에는 파일 목록).
- 2D 화면의 목록은 아직 기존 구조(탭 + 폴더 줄)를 쓴다.

## VR 버튼 구성 (자주 쓰는 것만 기본 화면, 나머지는 [더 보기])

버튼 글씨는 크기를 줄이거나 두 줄로 나눠 잘리지 않게 그린다(`core/label-fit.js`). 창은 한 번에 하나만 보이고, 화면 안에서도 목록 / 더 보기 / PLY 옵션 중 하나만 보인다.

|---|---|---|
| 공용 패널 | 소스·종류·정렬·목록 넘기기, [이전] [다음] [슬라이드쇼] [더 보기], 오른쪽 위 [✕] | 슬라이드쇼 간격, UI를 여기로 옮기기, 위치 초기화, (PLY) 크기 초기화·1:1 몰입·조작 안내·PLY 옵션, (영상·사진) 재생/10초/형식/재생 컨트롤 보기/진단 등, VR 종료 |

## 이전/다음·슬라이드쇼

- 2D 화면: 영상·사진·PLY 어느 것을 보든 화면 아래쪽 바에 [◀ 이전] [▶ 슬라이드쇼] [간격] [다음 ▶]이 있다. 키보드 ←/→(또는 [ ])도 된다.
- VR 패널: 맨 아래 줄에 [이전] [다음] [슬라이드쇼] [더 보기]가 있다(간격은 [더 보기]). 컨트롤러는 X 짧게(이전)·X 길게(다음).
- 영상·사진의 VR 재생 컨트롤: 기본 화면에 이전·다음·슬라이드쇼·목록이 있어 재생 조작과 한 곳에서 한다(아래 "버튼 구성"). 공용 VR 패널도 이 재생 컨트롤과 **같은 자리**(스크린 아래, 한 번 정하면 고정)에 열리지만 **한 번에 한 창만** 보인다: 패널이 열려 있는 동안 재생 컨트롤은 숨고, 패널을 닫으면 돌아온다([목록]·[재생 컨트롤 보기]로 서로 바꾼다).
- 슬라이드쇼: 간격(3·5·10·30초)을 고르고 시작하면 파일이 다 열린 뒤 그 시간이 지나면 다음 파일로 넘어간다. 영상은 간격이 아니라 **끝나면** 다음으로 넘어간다. 목록 끝에서는 처음으로 돌아간다. 직접 이전/다음을 눌러도 슬라이드쇼는 계속된다. 파일 열기에 실패하면 멈춘다.

## 다음 파일 미리 받기

PC·드라이브에서 연 PLY·사진은 다 열린 뒤 다음 파일(방금 이전을 눌렀다면 이전 파일)을 메모리에 미리 받아 두어, 넘길 때 기다리지 않는다.

- 한 번에 한 파일만 받아 둔다. 다른 파일로 가면 버린다. 영상을 보는 중에는 받지 않는다. 기기 파일·보관함은 이미 로컬이라 받지 않는다.
- 크기 한도: PLY 120MB, 사진 48MB를 넘으면 받지 않는다(`main.js`의 `setPrefetchLimit`).
- PLY는 뷰어의 `prefetch(item, file)`·`discardPrefetch()`가 받아 두고, 사진은 공용 코드가 Blob으로 받아 디코드까지 해 둔다.

## 뒤로 가기

Quest의 뒤로 가기(2D 창의 B 버튼·브라우저 뒤로)가 앱을 끄지 않는다. 한 번 누를 때마다 한 단계씩 돌아간다.

1. VR 중이면 VR을 끝낸다.
2. 항목을 보는 중이면 닫고 목록으로 간다.
3. 폴더 안이면 상위 폴더로 간다.
4. 목록 최상위에서 누르면 앱이 끝난다.
