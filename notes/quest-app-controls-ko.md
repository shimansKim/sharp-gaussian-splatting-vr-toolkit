# Quest 앱 조작표

Quest 3 컨트롤러 조작은 `quest-app/src/core/input-map.js`가 원본이다. 이 표는 그 `BINDINGS`를 사람이 읽기 쉽게 옮긴 것이다.
조작을 바꿀 때는 `input-map.js`를 먼저 고치고 이 표를 맞춘다.

## 모든 화면에서 같은 버튼

| 버튼 | 하는 일 |
|---|---|
| 트리거 | 선택. 레이로 가리킨 패널·재생 컨트롤 버튼을 누른다 |
| 그립 | 잡기 (뷰어마다 아래 표) |
| X (왼손) | 이전 파일 |
| A (오른손) | 다음 파일. 목록 끝에서는 처음으로 돈다 |
| B / Y 짧게 | **모든 UI 켜기·끄기** (공용 패널·영상/사진 재생 컨트롤·PLY 안내 한꺼번에). 켜고 꺼도 위치는 그대로 |
| B / Y 길게 (0.8초) | **UI를 지금 보는 곳으로 옮기기** (옮기면 UI가 켜진다) |
| 메뉴(≡)·Meta 버튼 | 시스템이 쓴다. WebXR로 앱에 전달되지 않아 앱에서는 쓸 수 없다. 그래서 UI 켜기·끄기는 B/Y로 한다 |

패널이 열려 있으면 두 스틱 상하로 목록을 넘기고(오래 밀면 빨라짐), 뷰어 조작은 막힌다.

## UI 위치 고정과 켜기·끄기

UI(공용 패널·영상/사진 재생 컨트롤·PLY 안내)는 **저절로 따라오거나 옮겨지지 않는다.** 정면 아래쪽에 머리 쪽으로 기울여 한 자리에 고정되어, 시야 한가운데를 가리지 않는다.

- 자리는 VR을 시작하고 헤드셋 자세가 들어온 직후 한 번 정해진다(그때의 머리 위치·정면 기준). 그 뒤 머리를 돌리거나 걸어도, 패널을 열고 닫거나 파일·형식을 바꿔도 **자리는 그대로**다. PLY에서 스틱으로 걸어 다니면 UI도 같이 따라가지만(방에 고정), 머리 움직임은 따라가지 않는다.
- **켜고 끄기**: B/Y를 짧게 누르면 모든 UI가 한꺼번에 꺼지고, 다시 누르면 같은 자리에 같은 상태로 돌아온다. UI가 켜져 있는데 보이는 것이 하나도 없으면(빈 화면) B/Y가 공용 패널을 연다.
- **옮기기(사람이 직접 할 때만)**: B/Y를 0.8초 이상 누르고 있거나, 패널의 [여기로 옮기기] 버튼을 누르면 UI가 지금 보는 방향 아래쪽으로 옮겨진다. 패널·재생 컨트롤·PLY 안내가 함께 옮겨진다.
- 그립·스틱·A/X는 UI 조작에 쓰지 않는다.

개발자용: 상태는 `quest-app/src/core/ui-state.js`(`ui.visible`, `ui.reference(camera)`, `ui.relocate(camera)`, 이벤트 `ui:visibility`·`ui:anchor`)이고, B/Y 처리는 `src/ui/ui-controls.js`다. 새 UI를 만들면 `ui.visible`이 꺼져 있을 때 띄우지 말고, 자리는 `ui.reference(camera)`로 얻는다.

## 뷰어별

| 입력 | PLY | 사진 | 영상 |
|---|---|---|---|
| 트리거 | 패널 선택만 | 패널 밖을 누르면 컨트롤 표시·숨김 | 패널 밖을 누르면 재생·일시정지 |
| 그립 | 한 손: 장면 잡아 이동·회전 / 두 손: 확대·축소 | 쓰지 않음(UI·화면이 저절로 옮겨지지 않게) | 쓰지 않음(UI·화면이 저절로 옮겨지지 않게) |
| 왼쪽 스틱 | 이동(앞뒤·좌우) | 좌우로 한 번 튕기기: 이전·다음 사진, 상하: 줌(위로 밀면 확대) | 좌우: 10초 되감기·빨리감기, 상하: 줌(위로 밀면 확대) |
| 오른쪽 스틱 | 좌우: 30° 스냅 회전, 상하: 높이 | 화면 회전 | 화면 회전 |
| 스틱 누르기 | 오른쪽: 맞춤/1:1, 왼쪽: 크기 초기화 | 오른쪽(R3): 화면을 지금 보는 방향 앞으로 맞춤 | 오른쪽(R3): 화면을 지금 보는 방향 앞으로 맞춤 |

스틱으로 장면을 돌리거나 움직일 때는 사람 요청대로 상하·좌우를 뒤집어서, **민 쪽으로 장면이 움직인다**(오른쪽으로 밀면 장면이 오른쪽으로 돈다). 부호는 `viewers/splat/splat-math.js`의 `STICK_INVERT` 한 곳에 있고, 영상·사진도 같은 규칙을 쓴다.

## 영상·사진 줌과 화면 자리

- 화면 자리는 세션을 시작하고 처음 파일을 열 때 한 번 정해지고, 파일을 넘기거나 형식·눈 바꿈을 바꾸거나 머리를 돌려도 **저절로 옮겨지지 않는다**. 스틱으로 돌려 둔 방향도 파일을 넘겨도 이어진다. 자리를 바꾸는 것은 R3와 재생 컨트롤의 [위치 맞춤](지금 보는 방향 앞으로, 돌려 둔 양도 지움)뿐이다.
- 줌: 왼쪽 스틱 상하(위로 밀면 확대)나 재생 컨트롤의 [−] [+]. 공용 패널이 열려 있으면 스틱 상하는 목록 넘기기이므로 줌하지 않는다.
  - 가상 스크린(평면 3D·2D): 스크린 크기(시야각) 배율 0.15~3배. 처음 크기는 가로 약 62°(예전 약 90°보다 작게).
  - 360/180: 시야각 확대 1~4배(원래보다 작게는 못 줄인다). 확대하는 동안에는 컴포지터 레이어로는 못 보여 줘 메시 경로로 그린다.
- 줌 값은 기기(localStorage, 키 sharp.media.zoom.v1)에 기억해 파일을 넘기거나 앱을 다시 켜도 유지한다. 스크린 배율과 구 확대는 따로 기억한다.

## Quest 기본 앱의 관례와 비교한 근거

- 트리거=선택: Meta 시스템 UI·브라우저·Skybox·Quest TV가 모두 같다.
- 그립=잡기, 양손 그립=크기: Horizon·3D 보기 앱의 관례.
- 오른쪽 스틱 좌우=스냅 회전: Meta 이동 표준. 영상 플레이어(Skybox·Quest TV)는 좌우가 되감기·빨리감기, 갤러리는 좌우 튕기기가 이전·다음 사진이다. 이 앱은 영상·사진에서 오른쪽 스틱을 화면 회전에 쓰므로(사람 요청) 그 동작들을 왼쪽 스틱 좌우에 둔다.
- B/Y=뒤로·메뉴, A/X=확인·다음 단계: 앱마다 다르지만 B/Y가 취소·메뉴인 점은 공통이다.

## 이전/다음·슬라이드쇼

- 2D 화면: 영상·사진·PLY 어느 것을 보든 화면 아래쪽 바에 [◀ 이전] [▶ 슬라이드쇼] [간격] [다음 ▶]이 있다. 키보드 ←/→(또는 [ ])도 된다.
- VR 패널: 이전·다음·슬라이드쇼·간격 버튼이 있다. 컨트롤러는 X/A.
- 영상·사진의 VR 재생 컨트롤: 맨 아래 줄에 같은 [이전] [번호] [다음] [슬라이드쇼] [간격] [목록]이 있어, 재생·형식 조작과 한 곳에서 한다. 공용 VR 패널(B/Y)도 이 재생 컨트롤과 **같은 자리**(스크린 아래, 한 번 정하면 고정)에 열려 서로 번갈아 나타난다.
- 슬라이드쇼: 간격(3·5·10·30초)을 고르고 시작하면 파일이 다 열린 뒤 그 시간이 지나면 다음 파일로 넘어간다. 영상은 간격이 아니라 **끝나면** 다음으로 넘어간다. 목록 끝에서는 처음으로 돌아간다. 직접 이전/다음을 눌러도 슬라이드쇼는 계속된다. 파일 열기에 실패하면 멈춘다.

## 다음 파일 미리 받기

PC·드라이브에서 연 PLY·사진은 다 열린 뒤 다음 파일(방금 이전을 눌렀다면 이전 파일)을 메모리에 미리 받아 두어, 넘길 때 기다리지 않는다.

- 한 번에 한 파일만 받아 둔다. 다른 파일로 가면 버린다. 영상을 보는 중에는 받지 않는다. 기기 파일·보관함은 이미 로컬이라 받지 않는다.
- 크기 한도: PLY 120MB, 사진 48MB를 넘으면 받지 않는다(`main.js`의 `setPrefetchLimit`).
- PLY는 뷰어의 `prefetch(item, file)`·`discardPrefetch()`가 받아 두고, 사진은 공용 코드가 Blob으로 받아 디코드까지 해 둔다.

## 뒤로 가기

Quest의 뒤로 가기(2D 창의 B 버튼·브라우저 뒤로)가 앱을 끄지 않는다. 한 번 누를 때마다 한 단계씩 돌아간다.

1. VR 중이면 VR을 끝낸다.
2. 항목을 보는 중이면 닫고 목록으로 간다.
3. 폴더 안이면 상위 폴더로 간다.
4. 목록 최상위에서 누르면 앱이 끝난다.
