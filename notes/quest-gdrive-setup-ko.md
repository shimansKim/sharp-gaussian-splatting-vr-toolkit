# 구글 드라이브 연결 설정 안내 (원할 때 이 순서로 켜면 됨)

> **폐기 결정:** 웹 앱·스토어 준비물은 폐기 결정됐으며 파일은 아직 남아 있다. 새 작업 대상이 아니다.
> Quest 네이티브 뷰어는 [Splatia](../quest-native/README.md)를 본다.

> Splatia의 Google Drive 접근은 [PC 경유 안내](../quest-native/docs/pc-source.md)를 본다.

**지금 하지 않아도 된다.** 설정하지 않은 상태가 기본이며, 앱의 다른 기능(기기 저장소, PC 폴더, VR 영상·사진, PLY 보기)은 전혀 영향받지 않는다.
구글 드라이브에서 바로 열고 싶어지면 아래 "설정 순서"대로 한 번만 하면 된다. 이미 만든 값이 있으면 6단계만 하면 된다.

설정 전에도 드라이브 파일은 열 수 있다. [드라이브] 탭이 알려 주는 대로 drive.google.com에서 내려받은 뒤 앱의 [기기에서 파일 열기]로 연다(아래 "설정하지 않으면" 참고).

Quest 앱에서 구글 드라이브의 PLY·영상·사진을 골라 여는 기능을 켜려면, 구글 클라우드에서 만든 값 3개가 앱에 들어 있어야 한다.
구글 정책상 **계정 주인(사람)만** 만들 수 있다. 에이전트가 대신할 수 없다.

## 만들 값 3개

| 값 | 어디에 쓰나 | 비밀인가 |
|---|---|---|
| OAuth 클라이언트 ID | 구글 로그인 | 아니다. 브라우저에 보이도록 설계된 값이다 |
| API 키 | 파일 선택 창(Google Picker) | 아니다. 단, 아래 5단계의 제한을 꼭 건다 |
| 프로젝트 번호 | 파일 선택 창이 고른 파일 접근을 앱에 연결 | 아니다 |

**클라이언트 보안 비밀(client secret)은 쓰지 않는다. 구글이 보여 줘도 복사하거나 공유하지 않는다.**

## 설정 순서

화면 이름은 구글이 가끔 바꾸므로 비슷한 이름의 메뉴를 찾으면 된다.

1. <https://console.cloud.google.com> 에 본인 구글 계정으로 로그인한다.
   위쪽 프로젝트 선택 > **새 프로젝트**에서 이름을 `sharp-quest-viewer`로 만든다.
   만든 뒤 **대시보드의 "프로젝트 정보"에서 프로젝트 번호**(숫자)를 적어 둔다. 프로젝트 ID(영문)와 다르다.
2. **API 및 서비스 > 라이브러리**에서 아래 두 개를 검색해 **사용**을 누른다.
   - Google Drive API
   - Google Picker API
3. **Google Auth Platform**(예전 이름 "OAuth 동의 화면")에서 다음처럼 만든다.
   - 앱 이름 `SHARP Quest Viewer`, 지원 이메일은 본인 이메일.
   - 대상(사용자 유형): **외부**.
   - **테스트 사용자**에 본인 구글 계정을 추가한다. 게시 상태는 "테스트"로 둔다. 혼자 쓰므로 심사가 필요 없다.
   - **데이터 액세스(범위)**에 `https://www.googleapis.com/auth/drive.file`을 추가한다.
     이 범위는 "앱에서 직접 고른 파일만" 열 수 있어서 드라이브 전체를 볼 수 없다.
4. **클라이언트**(또는 사용자 인증 정보 > 사용자 인증 정보 만들기 > OAuth 클라이언트 ID)에서 만든다.
   - 애플리케이션 유형: **웹 애플리케이션**.
   - **승인된 JavaScript 원본**에 아래 두 개를 넣는다(경로 없이 주소만).
     - `https://shimanskim.github.io`
     - `https://localhost:5173` (PC에서 개발·확인할 때만 필요)
   - 리디렉션 URI는 비워 둔다.
   - 만들면 **클라이언트 ID**(`...apps.googleusercontent.com`)가 보인다. 복사한다.
5. **사용자 인증 정보 > 사용자 인증 정보 만들기 > API 키**로 키를 만든다. 만든 직후 **키 제한**을 건다.
   - 애플리케이션 제한: **웹사이트**, 허용 주소 `https://shimanskim.github.io/*` (개발용으로 `https://localhost:5173/*`를 더해도 된다).
   - API 제한: **키 제한 > Google Picker API**만 선택.
6. 클라이언트 ID, API 키, 프로젝트 번호 3개를 커맨더에게 전달한다.
   커맨더가 `quest-app/src/config.js`의 `GDRIVE`에 넣어 반영한다.
   이 값들은 공개 저장소에 올라가도 된다(위 표 참고). 그래서 5단계의 키 제한이 중요하다.

## 처음 쓸 때(Quest에서)

1. 앱의 **[드라이브]** 탭 > **드라이브에서 파일 고르기**를 누른다.
2. 구글 로그인 창이 뜨면 본인 계정으로 로그인하고 허용한다. "확인되지 않은 앱" 안내가 나오면 **고급 > 이동**을 선택한다(테스트 상태 앱이라 정상이다).
3. 파일 선택 창에서 PLY·영상·사진을 고른다(여러 개 가능). 고른 파일이 목록에 남는다.
4. 로그인은 약 1시간 유효하다. 만료되면 파일을 열 때 로그인 창이 다시 뜬다.

앱은 **고른 파일만** 읽을 수 있다. 읽기 전용이며 드라이브 파일을 바꾸거나 지우지 않는다. [로그아웃(접근 해제)] 버튼으로 언제든 끊을 수 있다.

## 설정하지 않으면

- [드라이브] 탭에 "구글 드라이브 연결이 아직 설정되지 않았습니다"와 아래 우회 방법이 보인다.
- 앱의 다른 기능(기기 저장소, PC 폴더, VR 영상·사진, PLY 보기)에는 영향이 없다.
- **우회 방법**: Quest 브라우저에서 drive.google.com을 열어 파일을 내려받는다(Download 폴더에 저장). 그다음 앱의 **[기기에서 파일 열기]**로 연다.
  파일이 클 때는 PC에서 내려받아 PC 폴더 연결(`run_quest_pc_server.bat`)로 여는 편이 빠르다.

## 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| 로그인 창이 안 뜬다 | 팝업이 막혔다. 브라우저 사이트 설정에서 팝업 허용 후 다시 누른다 |
| `redirect_uri_mismatch`, `origin_mismatch` | 4단계의 JavaScript 원본이 실제 앱 주소와 다르다. 주소 끝에 `/`나 경로를 붙이지 않았는지 확인 |
| `access_denied` | 3단계 테스트 사용자에 로그인한 계정이 없다 |
| 파일 선택 창이 안 뜬다 | 2단계 Picker API 사용 설정 또는 5단계 API 키 제한(허용 주소) 확인 |
| 고른 파일이 열리지 않는다(404/403) | 프로젝트 번호가 틀렸거나, 다른 계정으로 로그인했다. 파일을 다시 고른다 |

## 확인되지 않은 부분(실기기에서 확인 필요)

- Quest 브라우저(와 TWA 앱) 안에서 구글 로그인 팝업이 정상으로 뜨는지는 문서만으로 확정하지 못했다.
  막히면 그 증상을 알려 주면 대안(리디렉트 방식)을 구현한다.
