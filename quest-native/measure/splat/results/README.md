## 2026-11-14 탐색 측정

이 기록은 최종 권장값을 확정하기 전의 실험이다.
`2026-11-14-exploration.json`은 조건별 요약이고, 같은 이름의 `.log`는 QNSplat·VrApi 원본이다.
각 조건은 약 8초이며, 헤드셋은 책상 위에 놓여 있었다.
착용 중 움직임과 장시간 안정성을 검증한 기록은 아니다.

- 기기: Quest 3, Adreno 740, 런타임 210.108.0, 72Hz.
- 입력: SHARP `001_frame_000005.ply`, 1,179,648 splat.
- 렌더러: 인계 커밋 `c6bc623`에 보존한 실험판. 새 공간별 표본 선택을 넣기 **전**이다.
- `R_`, `T_`, `M_`은 각각 앱을 다시 열고 같은 몰입 배치를 요청한 별도 실행이다.
- 아래 GPU 시간은 1초 평균들을 모아 낸 중앙값이다. 개별 프레임 p95가 아니다.
- 당시 로그에는 `sd2` 등 일부 손잡이가 빠져 있어 아래 실행 조건을 함께 읽어야 한다.
  이후 빌드는 QNSPLAT 줄마다 실제 손잡이를 기록한다.
- CSV의 기존 열 순서는 유지한다. 공유 모드와 손잡이는 logcat 원본으로 확인한다.

### 공유 정렬과 그리기 비용 분리

`R_` 조건: 전체 splat, 눈당 1680×1760, key=16, minc=0, draw=3, half=0.
별도 표시가 없으면 fov=0, sd2=8, acut=1, maxpx=2048이다.

| 조건 | fps | GPU ms | 판독 |
|---|---:|---:|---|
| R_s0: 눈별 전처리·정렬 | 18.0 | 53.27 | 비교 기준 |
| R_s1: 가운데 눈 전처리·공유 정렬 | 21.5 | 45.06 | 한쪽 compute 약 8ms 절감 |
| R_acut4: alpha cutoff 4/255 | 22.3 | 43.27 | 절감 폭이 작음 |
| R_tiny: 삼각형 면적을 거의 0으로 만듦 | 72.0 | 12.41 | 잘못된 그림을 내는 진단 전용 |
| R_nofrag: 모든 프래그먼트 버림 | 31.25 | 30.89 | 잘못된 그림을 내는 진단 전용 |
| R_noblend: 블렌딩 끔 | 22.45 | 42.84 | 잘못된 그림을 내는 진단 전용 |
| R_fov1: foveation 낮음 | 25.0 | 38.86 | 이 시점에서는 fill 비용 일부 절감 |
| R_fov2 / R_fov3 | 25.0 | 38.86 / 38.82 | 수준을 더 올려도 차이가 작음 |

면적을 없애면 12.41ms까지 줄었다.
이 장면은 정렬만 줄여서는 72fps를 달성하지 못한다.
래스터화·프래그먼트 처리 비용도 줄여야 한다.
`lc`는 공유 cull+preprocess, `rc`는 공유 prepare+sort, `ld`·`rd`는 눈별 draw다.
눈별 모드에서는 `lc`·`rc`가 각 눈의 전체 compute다.

### 지원 반경 비교

`T_` 조건은 `R_`와 같은 기본값에 shared stereo=1이다.
`sd2`는 가우시안 지원 반경의 제곱이다.
커널은 그 반경에서 alpha가 0이 되도록 보정한다.

| 조건 | fps | GPU ms |
|---|---:|---:|
| T_base: sd2=8 | 21.4 | 45.14 |
| T_sd6 | 24.4 | 39.44 |
| T_sd436 | 28.6 | 33.70 |
| T_sd32 | 32.7 | 29.36 |
| T_sd436_px133 / px64 | 28.55 / 28.6 | 33.81 / 33.75 |
| T_web5: sd2=4.36, maxpx=133, acut=4 | 29.25 | 32.88 |
| T_web5_half: 위 조건 + mediump | 29.3 | 32.89 |
| T_web5_minc06: 위 조건 + minc=0.6, highp | 30.7 | 31.45 |
| T_web5_s085: minc=0, scale=0.85, highp | 37.75 | 25.53 |

`T_web5`라는 이름은 웹 앱 안전 5의 반경·alpha 기준을 참고했다는 뜻이다.
Spark를 실행해 잰 웹 앱 기준선이 **아니다**.
maxpx 제한과 mediump 프래그먼트는 이 조건에서 유의한 이득을 보이지 않았다.
전체 splat을 유지한 sd2=4.36 화면에서는 피사체가 보존됐다.
다른 시점·가까운 물체·착용 상태의 화질은 따로 확인해야 한다.

### 기존 중요도 예산 선택은 화질 불합격

`M_` 조건: stereo=1, sd2=4.36, acut=4, maxpx=2048, minc=0, fov=0, key=16.

| splat 상한 | scale | fps | GPU ms |
|---|---:|---:|---:|
| 전체 | 0.65 | 52.15 | 18.59 |
| 800k | 0.65 | 68.25 | 14.15 |
| 600k | 0.65 | 72.0 | 11.73 |
| 400k | 0.75 | 72.0 | 11.29 |

**600k·400k의 72fps를 권장 성능으로 쓰면 안 된다.**
스크린샷을 확인하니 얼굴과 옷에 큰 구멍이 생겼다.
당시 `prune_budget`은 불투명도×월드 면적이 큰 splat부터 남겼다.
이 표본에서는 큰 배경이 남고 작은 전경 디테일이 사라졌다.
이후 구현은 Morton 순서의 구간마다 표본을 고르게 선택하고 면적을 보정한다.
새 표본 선택의 화질과 속도는 별도 실측으로 검증해야 한다.

### 첫 기준선과 구분할 것

사령관의 최초 측정은 전체·1.0에서 23.3fps/41.85ms였다.
위 `R_s0`는 18fps/53.27ms다.
시점과 기여 컬링 값이 다르므로 두 숫자를 전후 비교로 쓰지 않는다.
최종 전후 표는 한 세션의 같은 자세·입력·손잡이에서 비교해야 한다.
