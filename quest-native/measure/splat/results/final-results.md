# Quest 3 PLY 확정 측정

## 현재 기본값: 착용 확인 뒤 선명함 우선

2026-11-14 착용자의 요청에 따라 **안전 7·점 크기 1.10배·자동 조절 꺼짐**으로 바꿨다.
72fps보다 선명함을 우선한다.
HUD에는 별도 선명도 손잡이가 없다.
사람이 말한 “선명도 7”은 `화질`의 `안전 7`(`safe7`)이다.
`점 크기`는 `Options.pointSize` → `SplatEngine::SetPointSize`로 연결된다.
이는 투영 중심이나 장면 크기를 바꾸지 않고 splat 공분산의 투영 축을 1.10배로 키운다.

| 항목 | 현재 기본값 |
|---|---|
| 화질 | 안전 7 (`safe7`) |
| 공간 표본 상한 / 눈 해상도 배율 | 800k / 0.75 |
| 점 크기 / 지원반경² / alpha | 1.10 / 4.36 / 4/255 |
| 정렬 / 기여 컬링 / foveation | 공유 16bit / 0 / 0 |
| 자동 조절 | 꺼짐. 명시적으로 켜기 전에는 과부하에도 화질을 내리지 않음 |
| 새 조합의 고정 근거리 / 맞춤 fps | **50.6 / 72.0** — 첫 PLY, 각 120초·1초 창 중앙값 |
| 참고: 안전 7·점 크기 1.0의 과거 fps | 53.45 / 72.00 — 점 크기가 달라 새 기본의 성능으로 인용하지 않음 |

기존 `splat_options.txt`의 사용자 설정은 보존한다.
기존 설치에서는 PLY 옵션을 안전 7·점 크기 1.10·자동 조절 끔으로 맞춰야 한다.
렌더러·프리셋 사다리·자동 조절 알고리즘 자체는 바꾸지 않았다.
사람이 이전 APK에서 이 조합을 “합격선에 가까웠음”으로 평가했다.
착용자는 새 기본값의 움직임이 괜찮다고 확인했다.
입체감과 장시간 발열은 별도로 측정하지 않았다.

## 새 기본값과 배경 속도 옵션 실측

Quest 3에서 안전 7·점 크기 1.10·자동 조절 끔으로 각 시점을 120초씩 측정했다.
fps와 GPU 시간은 1초 평균 창의 중앙값이다.
고정 pose는 매 프레임 전처리·정렬을 강제한다.
근접 센서 자동화로 화면을 켠 미착용 상태에서 측정했다.
첫 시도는 화면이 꺼져 렌더 로그가 없어 무효로 처리했다.
설치 후 보존된 설정이 안전 5·자동 켬을 적용했으므로 HUD에서 안전 7·자동 끔으로 바꾼 뒤 측정했다.
사람의 결정에 따라 추가 PLY는 하나만 측정해 총 두 표본에서 마쳤다.

| PLY 로그 라벨 | 시점 | fps | GPU ms | 가시 점 |
|---|---|---:|---:|---:|
| `…Sixth-Sense…009_800k` | 근접 | 50.6 | 19.05 | 785,683 |
| `…Sixth-Sense…009_800k` | 맞춤 | 72.0 | 12.78 | 777,595 |
| `…16-4kUp-026_800k` | 근접 | 66.1 | 14.48 | 784,283 |
| `…16-4kUp-026_800k` | 맞춤 | 72.0 | 11.92 | 779,889 |

착용자는 B/Y로 사라진 옵션을 다시 열 수 있다고 확인했다.
새 기본값의 움직임도 괜찮다고 했다.
기본 화질·점 크기·자동 조절 값은 바꾸지 않는다.

### 배경 가볍게: 속도 우선

이 옵션은 기본 꺼짐이다.
켜면 앞쪽 화질을 기존보다 높이는 것이 아니라 원거리의 작은 점을 줄여 속도를 얻는다.
이전 전체 점 atomic 방식은 첫 PLY에서 켬일 때 근접 47.8fps·맞춤 68.7fps로, 끔보다 느렸다.
범위 수집을 1/16 표본으로 바꾼 뒤 근접 전처리 중앙값은 3.85ms에서 2.45ms로 줄어 끔의 2.47ms에 가까워졌다.
표본 범위는 정확한 전체 점의 최솟값·최댓값이 아니며 시야 변화에 한 계산 프레임 늦는다.

첫 PLY, 근접 고정 시점에서 각 조건을 20초 안정화 후 30초 측정했다.
`depthfloor`는 기준 픽셀 단위다.

| depthfloor | 가시 점 | fps | 전처리 lc ms |
|---:|---:|---:|---:|
| 0.1 | 785,683 | 48.65 | 2.45 |
| 1 | 781,123 | 50.8 | 2.46 |
| 4 | 696,529 | 53.7 | 2.21 |
| 16 | 602,059 | 57.4 | 2.00 |

16은 첫 PLY에서 끔 대비 약 23% 적은 점과 약 6.8fps 높은 수치를 보였다.
둘째 PLY에서는 784,283→737,868점으로 약 6% 줄었으나 66.1→64.7fps로 이득이 없었다.
서로 다른 길이의 측정과 순서·온도 차이가 있어 수치는 장기 성능 보장이 아니다.
착용자는 16의 켬 화면을 수용했고, 끔 화면이 거리에 관계없이 화질을 유지해 좋다고 했다.
사람은 옵션을 기본 끔인 속도 옵션으로 남기고 켬의 하한을 16으로 정했다.

### 근접 화질 향상 검토

둘째 PLY의 근접 고정 시점에서 배경 옵션을 켜고 각 조건을 20초 안정화·30초 측정했다.
기준인 안전 7·옵션 끔의 120초 결과는 66.1fps·14.48ms다.
점 상한 800k와 그 밖의 안전 7 조건은 유지했다.

| 렌더 배율 | depthfloor | 가시 점 | fps | 전처리 lc ms | GPU ms |
|---:|---:|---:|---:|---:|---:|
| 0.75 | 16 | 737,868 | 64.7 | 2.37 | 14.67 |
| 0.90 | 16 | 738,075 | 50.0 | 2.36 | 18.75 |
| 1.00 | 16 | 738,157 | 44.1 | 2.37 | 21.48 |
| 1.00 | 0 | 786,347 | 42.9 | 2.58 | 22.21 |

배율을 높인 비용이 배경 점 절감 여유보다 커서 같은 fps에서 근접 화질을 올리지 못했다.
SHARP의 SH는 0차이며 기본 로드도 SH 0차로 제한하므로 차수를 늘려도 원본에 없는 정보를 복원할 수 없다(`quest-native/app/src/main/cpp/splat/engine/splat_scene.h:17-21`).
로드 예산 확대 및 버퍼 초과 시 앞쪽 우선 수용은 추가 설계와 실측이 필요한 별도 작업이며 이번 범위에서 구현하지 않았다(`quest-native/app/src/main/cpp/splat/engine/quality.cpp:31-36`, `quest-native/app/src/main/cpp/splat/third_party/pocketsplat/render/shaders/splat_preprocess.comp:248-251`).

## 이전 기본 안전 5의 측정 기록

**이전 기본 안전 5는 공간 표본 600k·눈 해상도 0.70·지원반경²3.2로 확정했다.**
SHARP 원본 1,179,648개를 공간별로 줄인 결과다.
원본 전체를 그대로 그려서 72fps를 달성했다는 뜻은 아니다.
고정 근거리와 고정 맞춤 보기에서 각각 130초 동안 72fps·Stale0을 확인했다.
원격 손잡이를 모두 비우고 최종 후보 APK를 다시 연 실제 추적 모드에서도 130초 동안 72fps·Stale0이었다.

전체 splat을 유지하면 공유 정렬·배율 0.60·지원반경²3.2에서도 근거리 58.3fps/16.69ms였다.
전체 splat을 유지한 72fps는 달성하지 못했다.
다른 알고리즘으로도 불가능하다는 결론은 아니다.

캡처에서 기본값은 원본보다 약간 부드럽지만 얼굴·머리카락·옷 글자가 유지되고 구멍이 없었다.
이 비교를 검토한 뒤 기본값을 승인했다.
착용 상태의 입체감·움직임·멀미는 확인하지 않았다.
표본은 개인 자료이므로 PLY와 인물 캡처를 저장소에 넣지 않았다.
비교 캡처는 별도 비공개 증거로 보존한다.

## 적응 품질 기준

현재 기본은 자동 조절을 끈다.
사용자가 자동 조절을 켰을 때만 아래 `AdaptConfig`를 적용한다.

| 항목 | 값 | 근거 |
|---|---:|---|
| 연속 과부하 | 4초 | 짧은 로드·클럭 전환 한 번에 해상도를 바꾸지 않음 |
| 프레임 초과 | 예산×1.05 | 72Hz에서 평균 약 68.6fps 미만을 지속 과부하로 봄 |
| GPU 초과 | 예산×0.95 | 72Hz에서 13.19ms. 이전 안전 5 근거리 p95 12.40ms는 유지하고 여유 없는 상위 조건은 내림 |
| 변경 간격 | 8초 | 스왑체인을 연속 재생성하지 않음 |
| 회복 여유 | GPU<예산×0.65, 프레임은 제시간 | 배율 증가의 제곱 비용을 감당할 여유를 요구 |
| 회복 시간 | 15초 | 잠깐 쉬운 시점으로 돌아왔다고 즉시 올리지 않음 |
| 자동 바닥 | 안전 1 | 하위 단계를 내려도 얼굴을 전부 지우는 중요도 예산 선택은 사용하지 않음 |

자동은 해상도·지원반경·alpha 기준·기여 컬링만 바꾼다.
사용자가 고른 splat 상한·정렬 키·공유 여부는 유지해 자동 파일 재로드와 파이프라인 재생성을 피한다.
따라서 전체 splat을 고른 무거운 장면은 자동 최저 단계에서도 72fps가 안 나올 수 있다.
그때 HUD 진단에 상한이 낮은 프리셋을 고르라는 안내를 표시한다.
이전 안전 5 측정창으로 재생한 PC 시험에서는 단계가 불필요하게 내려가지 않았고, 과부하·회복·바닥 시험도 통과했다.
4/8/15초는 이 측정에 맞춰 정한 제어 정책이지 모든 장면에서 최적이라고 검증한 상수는 아니다.

## 선택한 최적화와 버린 후보

- 공유 전처리·정렬: 같은 고정 근거리에서 55.99→47.70ms. 눈별 draw는 남긴다.
- 지원 반경·해상도 축소: fill 비용을 줄인다. [탐색 기록](README.md#2026-11-14-탐색-측정)의 tiny/no-fragment 진단도 fill 병목을 가리킨다.
- 공간별 표본+면적 보정: 기존 world-area 중요도 선택이 지우던 얼굴·옷을 보존했다.
  원본보다 약간 부드러운 손실성 근사다.
- triangle이 quad보다 빨랐다. mediump 프래그먼트와 maxpx 제한은 탐색 조건에서 이득이 작아 기본에 쓰지 않는다.
- 멀티뷰·타일 누적의 조기 종료는 구현·실측하지 않았다. 효과가 없다고 결론 내리지 않는다.
- 공유 공분산은 가까운 큰 splat이나 비대칭 시점에서 차이가 날 수 있다. 고화질의 눈별 경로를 남겼다.

## 무효 실행과 한계

- `U_reference`: 가시 수가 117만→왼 13만/오른 39만으로 급변하고 그림이 화면 밖으로 밀려 무효 처리했다.
  이후 고정 시점 모드와 가시 수 20% 급변 검사를 추가했다.
- `G_full055_sd32`: 요청 0.55를 호스트가 0.60으로 제한했다. 요청값 불일치로 무효 처리하고 0.60으로 다시 쟀다.
- 최초 중요도 상위 400k·600k의 72fps 결과는 전경에 구멍이 있어 화질 불합격이다.
- 위 과거 측정 당시에는 다른 PLY, 더 가까운 접근, 빠른 머리 이동, 장시간 착용 발열을 확인하지 않았다.
- 웹 앱(Spark)의 같은 PLY·Quest 3 실측 기록은 저장소·notes·이전 목표 기록에서 찾지 못했다.
  Spark와의 속도 우위를 주장하지 않는다.
- 사진·PLY·인물 캡처는 저장소에 포함하지 않는다.
